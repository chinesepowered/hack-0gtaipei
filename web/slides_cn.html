為什麼有兩隻 Beagle

帶鑰匙的 Beagle

一個普通的 Agent 程式，持有我們自己產生的私鑰。

用 verify_tee 呼叫 0G Compute，然後簽一張收據：這把鑰匙為這個任務產出了這個答案，並附上 TEE 的推理證明。

TEE 證明模型誠實地跑過了。但沒有任何東西證明這把鑰匙屬於一個真實、未被竄改的 Agent。誰拿到鑰匙檔，誰就能簽任何東西。

回答的是：真的有模型產出這個答案嗎？

密封版 Beagle，Agentic ID #383

跑在 0G attestor 佈建的 TEE 沙箱裡。簽章金鑰由 0G 的金鑰服務在 TEE 內部衍生，連擁有者都讀不到。

每一則回應都蓋上 X-Agent-Proof，記載是哪個 Agent、哪個執行環境、哪一次交換、誰可以兌現。託管合約拿它去比對鏈上的 getAgentSeal。

回答的是：是這個特定、未被竄改的 Agent 服務了這個特定客戶嗎？

帶鑰匙模式是今天任何 Agent 都能用的基準線；密封模式是 0G 身份層額外提供的，也是託管合約能安全放款所需要的。

預期會被問到的問題

為什麼不直接相信 TEE 的推理證明？
它證明模型產出了這段輸出，但不證明是哪個 Agent 服務了哪個客戶。印章補上「是誰」，而託管合約需要「是誰」才能付款。
擁有者能偽造印章嗎？
不能。AgentSeal 金鑰由 0G 的 KMS 在 TEE 內衍生，從未離開。擁有者可以啟動、停止、重置 Agent，但無法以它的身份簽名。
怎麼防止印章被重複使用？
託管合約記錄每一枚已付款的印章摘要，第二次提交會以「seal reused」回滾。信譽登錄合約用 nonce 做同樣的事。
不靠我們，任何人都能驗證嗎？
可以，離線且免 gas。從標頭重建摘要、還原簽章者、和鏈上的 getAgentSeal 比對。合約原始碼已在 chainscan 驗證。
鏈上實際有什麼？
ProofEscrow 在 0xac8f…fb95，AgenticID 合約在 0x5BB5…B24A，Agent 383 的印章地址 0x9891…2c0b，全部在 0G Galileo。
怎麼賺錢？
結算手續費，或按印章計價。交易量隨 Agent 呼叫量成長。同一枚印章也能寫入 ERC-8004 信譽，讓評價自帶收據。
